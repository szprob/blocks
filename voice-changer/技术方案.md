# 实时变声软件技术方案(男声 → 温柔女声)

> 目标:输入自己的声音,实时输出「温柔女声」音色;自己写代码做成应用,双平台(Mac + Windows),第一版先在 Windows + NVIDIA 上跑通。
> 技术路线:**RVC 语音转换引擎 + 客户端/服务端(C/S)架构 + Python 图形界面**

---

## 0. 先搞清楚:这到底是什么技术

变声 = **语音转换(Voice Conversion, VC)**:保留你说话的**内容、节奏、情绪**,只把**音色**换成另一个人。它和 TTS(文字转语音)完全不同——TTS 是「给文字生成声音」,VC 是「给声音换皮」。

本方案要做的是:
- 麦克风采集你的男声 → 实时送进 RVC 模型 → 输出女声 → 送到虚拟麦克风 → Zoom/Discord/OBS 等软件把变声后的声音当成你的麦克风输入。

**男声变女声的关键动作是变调(Transpose)+12 半音(高一个八度)**:男声基频通常 100–150Hz,女声 200–300Hz,+12 正好翻倍进入女声音域;再配合共振峰/音色模型调出「温柔」感。

---

## 1. 方案选型(为什么是 RVC)

| 方案 | 是否要训练 | 实时变声 | 双平台 | 许可 | 结论 |
|---|---|---|---|---|---|
| **RVC** | 要(约 10 分钟干净音频),但**可直接用现成模型跳过** | ✅ 成熟实时 GUI | Win CUDA / Mac MPS | MIT | **选它做主引擎** |
| Seed-VC | 不用,1~30 秒零样本克隆 | ✅ 延迟约 300ms | Win/Mac/Linux | GPL-3.0 | 仓库已归档(2025-11-21),不做主引擎;可作离线备选 |
| GPT-SoVITS / So-VITS-SVC | 要,数据量/调参更重 | 弱 | 复杂 | 开源(商用需查) | 音质上限高,适合唱歌/后期,不适合实时 |

选 RVC 的理由:
1. 社区现成女声模型最多(妙音、HuggingFace、模型工坊),「温柔女声」可直接下,零训练起步。
2. 实时链路最完整:实时 GUI、虚拟麦克风、音色预设参数都有现成参考。
3. Windows 走 CUDA 延迟最低;Mac 有专门的 Apple Silicon 优化分支(MPS 加速)。
4. MIT 许可,封装成自己的应用无授权包袱。

> 注意:音色克隆别人声音涉及肖像权/声音权,**只用于克隆自己或已获授权的声音**,现成模型也要看清模型站的授权范围。

## 2. 整体架构

```
┌──────────────────────────┐        WebSocket(PCM 帧)        ┌─────────────────────────┐
│  Python 客户端应用        │  ─────────────────────────────→  │  VC 推理服务(Python)     │
│  · Tkinter/PyQt 界面      │                                  │  · 加载 RVC 女声模型     │
│  · sounddevice 采集麦克风 │  ←─────────────────────────────  │  · 推理:男声→女声        │
│  · 分帧(20ms/帧)         │        变声后 PCM 帧              │  · Win=CUDA / Mac=MPS    │
│  · 播放到虚拟麦克风       │                                  │  · 可放本机/另一台PC/云  │
└────────────┬─────────────┘                                  └─────────────────────────┘
             │ 虚拟声卡输出
             ↓
    会议/直播软件(Zoom / Discord / OBS)把它当成麦克风输入
```

为什么拆成两层:
- UI 用一套跨平台代码;推理服务按平台换后端(MPS / CUDA),互不耦合。
- 推理是重活,放另一台机器或云 GPU 也不影响打游戏/直播的机器 —— 这正是 w-okada voice-changer 的 C/S 模式。
- 以后加音色、调参只动服务端;改界面只动客户端。

**虚拟声卡路由**:
- Windows:VB-CABLE / Voicemeeter(客户端输出 → CABLE Input,会议软件输入选 CABLE Output)。
- Mac:BlackHole 创建虚拟声卡(客户端输出 → BlackHole,会议软件输入选 BlackHole)。

**延迟预算**(实时通话目标 < 300ms):
- 采集缓冲 20ms + 网络往返(本机 < 5ms)+ RVC 推理(4080 约 30–60ms)+ 播放缓冲 20ms ≈ 100ms 左右,可接受。

## 4. 模型准备(两种来源)

### A. 现成女声模型(推荐起步)
按 3.4 下载 `.pth` + `.index`,零训练,几分钟出效果。选模型时看:
- 采样率:40k(旧)/48k(新更清晰),要和推理设置一致。
- 是否带 F0:男变女要带 F0 的模型才能用 `Transpose`。
- 模型授权:只做个人/授权用途。

### B. 录一段女声零样本克隆(可选,Seed-VC)
如果找不到合适的现成模型,可以用 Seed-VC 丢 5~30 秒女声参考音频做 zero-shot 克隆(无需训练)。但它仓库已归档、实时延迟偏高(~300ms+),建议只做**离线验证**:把你的录音转成目标音色听效果,满意后再想办法固化为 RVC 模型或接受延迟。

### C. 自己训练专属模型(进阶)
想长期用、音色调到最贴合:
- 准备 ≥10 分钟干净女声录音(无伴奏、无噪音),按 RVC WebUI 的 Training 页走。
- 切分 → 提取 F0 → 训练 → 得到 `.pth` + `.index`。
- Windows 上训练速度可接受;Mac M1/M2 也能训练但部分算子 MPS 不支持会回退 CPU,较慢。

## 5. 推理服务设计

把 RVC 推理封成一个 WebSocket 服务。**先不要从零写 RVC 推理核心**——复用 RVC 仓库的推理类。

### 5.1 参考实现
- `w-okada/voice-changer` 已经实现了完整的 C/S 实时变声 + API,直接读它的 `VoiceChanger` 服务代码和音频分帧逻辑,能省掉大量坑。
- RVC 仓库里 `infer/modules/vc/` 是推理核心,`infer-web.py` 展示了加载模型、提取 F0、推理的调用方式。

### 5.2 服务接口约定(建议)

```text
WebSocket 地址: ws://127.0.0.1:8765
握手消息(JSON): {"type":"config","model":"温柔女声.pth","transpose":12,"index_rate":0.7}
音频帧: 二进制,20ms PCM,16kHz,单声道,int16(320 样本 = 640 字节)
返回:   二进制,同长度变声后 PCM(具体长度取决于模型采样率,按协议对齐)
控制消息: {"type":"switch_model", ...} / {"type":"set_param", ...}
```

### 5.3 推理循环伪代码

```python
# 伪代码:展示调用链,真实实现复用 RVC / w-okada 的推理模块
import numpy as np

class VCService:
    def __init__(self, model_path, index_path, transpose=12):
        self.model = load_rvc_model(model_path, index_path)  # 复用 RVC 推理类
        self.transpose = transpose

    def infer(self, pcm_int16: np.ndarray) -> np.ndarray:
        # 1) int16 -> float32 [-1,1]
        audio = pcm_int16.astype(np.float32) / 32768.0
        # 2) 提取 F0(rmvpe),男变女升 +12 半音
        f0 = extract_f0(audio, method="rmvpe")
        f0 = f0 * (2 ** (self.transpose / 12))
        # 3) RVC 推理(内容特征 + 检索 + 声码器)
        out = self.model.infer(audio, f0=f0, index_rate=0.7)
        # 4) float32 -> int16
        return np.clip(out * 32768, -32768, 32767).astype(np.int16)
```

要点:
- **必须做分帧 + 重叠相加(STFT/OLA)** 或按模型的帧长对齐,否则拼接会有咔哒声。w-okada 已经处理好,直接复用。
- F0 提取是男变女的核心,一定要用带 F0 推理的路径。
- 采样率统一(建议客户端采集 16k,模型 48k 时服务端重采样)。
- 服务端要能热切换模型和参数(JSON 控制消息)。

## 6. 客户端应用(Python 图形界面)

### 6.1 技术栈
- 界面:**Tkinter**(零依赖,够用)或 **PyQt**(更好看)。
- 音频采集/播放:**sounddevice**(基于 PortAudio,跨平台)。
- 网络:**websockets** 或 `websocket-client`。
- 依赖安装:
  ```bat
  pip install sounddevice soundfile numpy websockets pyaudio
  ```
  > Windows 上 `sounddevice` 自带 PortAudio,一般不用额外装。

### 6.2 程序骨架

```python
import asyncio, sounddevice as sd, numpy as np, websockets, json

SAMPLE_RATE = 16000
FRAME_MS = 20
FRAME_SIZE = SAMPLE_RATE * FRAME_MS // 1000  # 320 samples

async def voice_loop(ws, device_in, device_out):
    loop = asyncio.get_event_loop()
    # 采集回调:把麦克风数据放进队列
    q_in = asyncio.Queue()
    def cb(indata, frames, time, status):
        q_in.put_nowait(indata[:, 0].copy())
    stream_in = sd.InputStream(samplerate=SAMPLE_RATE, channels=1,
                               dtype='int16', device=device_in, callback=cb)
    stream_out = sd.OutputStream(samplerate=SAMPLE_RATE, channels=1,
                                 dtype='int16', device=device_out)
    with stream_in, stream_out:
        # 握手:配置模型和变调
        await ws.send(json.dumps({"type":"config",
                                  "model":"温柔女声.pth","transpose":12}))
        while True:
            pcm = await q_in.get()          # 取一帧男声
            await ws.send(pcm.tobytes())    # 发给推理服务
            data = await ws.recv()          # 收变声后女声
            audio_out = np.frombuffer(data, dtype=np.int16)
            stream_out.write(audio_out)     # 写虚拟麦克风

async def main():
    async with websockets.connect("ws://127.0.0.1:8765") as ws:
        await voice_loop(ws, device_in=None, device_out=None)  # 用默认设备

asyncio.run(main())
```

> 这是最小骨架:`device_out` 要选虚拟声卡(VB-CABLE Input / BlackHole)。真实项目要加:设备选择下拉框、音色/变调滑块、连接状态、异常处理、缓冲抖动处理(jitter buffer)。

### 6.3 界面元素(第一版够用)
- 麦克风 / 输出设备下拉框
- 模型选择 + 变调滑块(6~14 半音,默认 12)
- Index Rate 滑块(0~1,默认 0.7)
- 「开始变声 / 停止」按钮
- 延迟、状态显示

## 7. 虚拟声卡与会议软件联调

### Windows(VB-CABLE)
1. 装 VB-CABLE,系统里会出现 `CABLE Input`(播放端)和 `CABLE Output`(录制端)。
2. 客户端 `device_out` 选 `CABLE Input`。
3. Zoom/Discord/OBS 的麦克风选 `CABLE Output`。
4. 戴耳机监听,避免扬声器声音被麦克风再次采集造成啸叫/回声。

### Mac(BlackHole)
1. `brew install blackhole-2ch`。
2. 客户端输出到 BlackHole,会议软件输入选 BlackHole。
3. Mac 上 RVC 推理换 MPS 后端(见第 8 节),延迟会比 Windows 高一些,先接受。

## 8. 参数调优:调出「温柔女声」

| 参数 | 建议值 | 作用 |
|---|---|---|
| Transpose(变调) | +12(可试 10~14) | 决定音高;太低像大叔,太高像卡通音 |
| F0 提取算法 | rmvpe | 防止男声变女声时「哑音/破音」,比 crepe 更好更快 |
| Index Rate | 0.6~0.8 | 越高越像目标音色,但可能损失咬字;太高会有「电音」 |
| 共振峰(Formant) | 适度上移 | 让音色更「女」、更柔;RVC 部分 GUI 有此参数 |
| 保护/降噪 | 开 | 抑制底噪和机械感 |

「声音假/铁皮机器人」的排查顺序:
1. 输入音量太小或爆音 → 调麦克风增益,输入保持在 -12dB 左右。
2. 模型不匹配(40k 模型用了 48k 设置)→ 对齐采样率。
3. Index Rate 过高 → 降到 0.5~0.7。
4. 变调过头 → 从 +12 往回收到 +10。
5. 用了不带 F0 的模型 → 换带 F0 的模型。

## 9. Mac 适配(第二版)

- 用 RVC 的 Apple Silicon 优化分支 `qingbo1011/RVC-WebUI-MacOS`,已修好:Tcl/Tk 冲突、OpenMP 崩溃、MPS 回退、Gradio 超时。
- 关键环境变量(启动脚本已自动设置):
  ```bash
  export PYTORCH_ENABLE_MPS_FALLBACK=1   # 算子不支持时回退 CPU,不崩
  export KMP_DUPLICATE_LIB_OK=TRUE       # 防 OpenMP 重复加载崩溃
  ```
- 模型放 `assets/weights/` 和 `assets/indices/`,WebUI 里点「刷新音色列表」。
- Mac 部分算子 MPS 不支持会回退 CPU,训练和实时推理都比 Windows 慢;如果 Mac 实时延迟不可接受,可让 Mac 只做客户端 + 推理服务跑在 Windows 机器/云 GPU 上(架构天然支持)。
